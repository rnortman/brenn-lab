The runner can write a `results.json` holding a record that the run-directory reference does not allow, and the run's assessment then refuses the whole run. It happens when a capture's recorder reader fails, or a play's thread fails before reporting its end, and the error is raised by a command of the script's own: a capture role's `start` or `stop`, a playback role's `play` or `stop`. The run ends `failed`, naming the role's raise (`role_raised`), whether or not the script catches the error. That capture's or play's record keeps `ended` `null`, a play's `restored` too, where the reference gives `stopped` or `failed` for a capture, `completed`, `stopped` or `failed` for a play, and true or false for `restored`. `lab assess` and the assessment a run makes at its end read the value as a wrong shape and refuse the run as `unreadable`: none of its captures is measured and no finding names the failure. The same error raised at release leaves no `results.json`, and that run is assessed in part.

Done when no `results.json` the runner writes holds a record the reference does not allow, whatever a role raised and whatever the script did with it; the assessment of such a run measures its captures and names the failure as a finding; and default-check tests hold both for a capture and for a play. The record's repair is in the roles' failure paths, the playback role's among them.
