The recorder pinned from brenn-pod is built with the build script of brenn-pod's `build-id` crate switched off, and `MODULE.bazel` gives the compiler the three values that script would set: `HIL_BUILD_COMMIT`, `HIL_BUILD_DIRTY` and `HIL_BUILD_SOURCE`. The script is off because it runs the host's git even when the commit is declared to it, and nothing in a build action here may reach for a host program. The cost is that this repository states names and a rule that are the crate's own: a brenn-pod revision that renames one fails this build, and one that changes what a declared build reports is misreported until the hardware lane's comparison with the recorded transcripts shows it. brenn-pod tracks its half as `build-id-declared-build-runs-git`. Done when brenn-pod's `build-id` builds from a fetched revision without running any program, given only the commit it documents declaring, the pin has moved to such a revision, and the annotation here gives that one value.
