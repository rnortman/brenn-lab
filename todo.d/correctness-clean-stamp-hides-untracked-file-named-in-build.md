The harness's build stamp says `dirty` false for a runner that holds a file no commit has, when a commit names a new source file in a BUILD file and leaves the file itself untracked (for example after `git commit -a`). The pre-commit hook runs `make check` against the working tree, where the file exists, so the gate passes a commit that cannot be built from its own tree. `dirty` keeps brenn-pod's meaning, a tracked file differs from the commit, so the stamp alone cannot catch this. Decide between a gate rule (refuse a commit while a file under `brenn_lab/`, `tools/` or `examples/` is untracked and not ignored, or check the staged tree rather than the working tree) and a second meaning of `dirty` for the harness's own entry; the reference document's *What `dirty` means* states the gap until then.
