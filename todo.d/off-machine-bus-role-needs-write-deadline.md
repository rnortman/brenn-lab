brenn-lab will drive device roles on other machines over the brenn bus, through brenn's Python binding. The binding's client has no deadline on a network write. When the server stops reading while its connection stays open (its host has left the network without closing the connection, or the server process is alive and stuck) and the client has enough unsent data that a write blocks (one large body, or a run of publishes), publishing and subscribing time out while the client still reports itself attached, and unsubscribing and closing the client block. Ctrl-C does not interrupt the close, and interrupts the unsubscribe only on the main thread. With the host gone they block until TCP gives up, about fifteen minutes with the kernel's default retries; with a stuck server process they block for as long as the process stays that way. The defect and its fix are in brenn's attach client, tracked in brenn's `TODO.md` as `errhandling-blocked-write-stalls-supervisor-and-close`. A machine leaving the network is an ordinary event in a lab, so until the brenn commit brenn-lab pins has the fix, no role is driven over the bus to a server on another machine. A role carried between processes on one machine does not wait for it: there a stuck server can be killed, and the kill resets the connection. Done when the brenn commit `MODULE.bazel` pins has that entry done, and a brenn-lab test that has been seen to hang against a brenn commit without the fix shows a client whose server has stopped reading closing within a bound the test states.
