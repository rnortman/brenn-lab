On linux aarch64 the gate tools are built against the host's C library. The C toolchain's sysroot is pinned for linux x86_64 only, so on an aarch64 host the LLVM toolchain falls back to the host's own headers and libc, and building `//tools/scrub` and `//tools/allthechanges` there needs them installed. That is a hole in the rule that nothing in a build action reaches for a host-installed program. Pin a sysroot for linux aarch64 in `MODULE.bazel`, as one is pinned for x86_64, so the gate tools build there with the host prerequisites `AGENTS.md` states for x86_64. Deferred because there was no aarch64 host to verify a pin on, and an unverified pin would be a claim nobody tested. Done when `make check` passes on a linux aarch64 host that has only those prerequisites, and `AGENTS.md` and the two comments in `MODULE.bazel` no longer state an aarch64 exception. The comment sits above the sysroot in `MODULE.bazel`.
