The run-output directory globs in `.gitignore` (`logs/`, `runs/`, `captures/`, `recordings/`, `framelogs/`, `segments/`) are unanchored, so a source package with one of those names anywhere in the tree is ignored by git, skipped by ruff and by the tree scan, and still built by Bazel locally: the local gate passes and a fresh clone fails. Once the harness decides where runs are written, anchor these globs to that location (or to one run-output root), and check that a run's non-audio files (manifests, notes, device metadata) are still kept out wherever a run can write them. The comment sits above the run and capture directory globs in `.gitignore`.
