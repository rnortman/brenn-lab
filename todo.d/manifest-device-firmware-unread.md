A run's manifest records the recorder program's build, the capture device's identity as ALSA and USB give it, and the parameters the device granted. It does not record the device's own firmware version or configuration (for an XVF3800: the chip's firmware version and its output routing), and says so explicitly, because nothing the harness calls reads them: brenn-pod's recorder performs no device control, and brenn-pod's entry `xvf-control-on-usb-audio-image` is the work that reads them for a Flex on the six-channel USB image. Until then a run cannot say which chip firmware or routing produced its channels. Done when, for a device whose firmware and configuration brenn-pod reads and records, the manifest carries them as read from brenn-pod's output, a test holds that, the reference document for the run directory describes the fields, and a device for which they still cannot be read keeps the explicit statement. The `TODO(manifest-device-firmware-unread)` comment sits in the capture role's recorder adapter, where the not-read statement is made.
