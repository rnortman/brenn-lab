The PreToolUse scrub hook builds the scanner from the working tree on every Write or Edit and blocks the write when that fails. An edit that breaks a file the scanner's build reads (for example `MODULE.bazel`, `.bazelversion`, `.bazelrc` or anything under `tools/scrub/`) passes its own scan, because the hook ran before the file changed, and then blocks every later write, the edit that would repair it included. A two-step edit to one of those files (a target first, its `load` second) is enough to trigger it. The recovery in use is the one `AGENTS.md` states under Gates. That leaves the defect in place. Make the hook repairable through itself, for example by scanning with the last good build of the scanner when the current tree's build fails, without the gate ever failing open. Done when a broken build file can be repaired by an ordinary edit and a scanner that cannot run still blocks. The comment sits in `.claude/hooks/scrub-check.sh`.
